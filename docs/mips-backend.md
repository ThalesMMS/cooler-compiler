# MIPS backend (PA5)

The optional MIPS backend compiles a type-checked COOL program to SPIM
assembly that follows the Cool runtime system's conventions (the
`trap.handler` contract). It is opt-in: the Go VM and the educational
pseudo-assembly remain the default for `coolerc run`, `coolerc emit assembly`,
and the GUI.

- **GUI:** the **MIPS** tab next to **Assembly** shows the generated `.s`
  and exports or shares it (**Export .s / share**, or *MIPS assembly (.s)* in
  the export menu). **Run in simulator** executes it inside the app; see
  [Embedded simulator](#embedded-simulator).
- **CLI (secondary):** `coolerc emit assembly --target=mips [file.cl ...]`
  (`--target=vm`, the default, keeps the educational pseudo-assembly) and
  `coolerc run --target=mips [file.cl ...]` (embedded simulator).

Generation runs the ordinary front-end (either `--frontend`) and semantic
analysis; a program with errors produces its diagnostics and no assembly.
Byte-identical output with the reference `cgen` is not a goal; program
behavior and runtime errors are.

## Lowering strategy

Code is generated by walking the type-checked AST, not the stack IR. The IR
is verified and source-linked, but it erases what MIPS code needs at every
step: static types for dispatch-slot lookup, attribute offsets, class tags
for `case`, and the Cool calling convention. Walking the AST attaches that
metadata directly; the result is still a stack machine (the course handout's
suggested design), with temporaries on the MIPS stack.

## Object layout

Every object, prototype, and constant has this layout (offsets in bytes from
the object pointer, which points at the tag):

| Offset | Contents |
| ---: | --- |
| -4 | garbage-collector eyecatcher, the word `-1` |
| 0 | class tag |
| 4 | object size in words, including the three header words |
| 8 | pointer to the class's dispatch table |
| 12 + 4*k | attribute k |

Attributes are laid out parent first: a class's slots begin with all of its
ancestors' attributes in inheritance order, followed by its own attributes in
declaration order, so an inherited attribute has the same offset in every
subclass. Basic classes use the runtime's representation: `Int` and `Bool`
hold a raw 32-bit value at offset 12; `String` holds a pointer to an `Int`
length object at offset 12 followed by the NUL-terminated bytes, padded to a
word boundary (`.align 2`).

Each class has a prototype `C_protObj` in the data segment, preceded by the
`-1` eyecatcher. Attributes without an initializer start from the
prototype's defaults: `Int` attributes point to the shared constant 0,
`String` to the empty string, `Bool` to `bool_const0`, and every other type
is void (0). `new C` copies the prototype with `Object.copy` and then calls
`C_init`.

Class tags are assigned in depth-first preorder of the inheritance tree,
starting at `Object` = 0, with `IO`, `Int`, `Bool`, and `String` as the
first children of `Object` and user classes in program order. A class's
descendants therefore occupy the tag range `[tag, maxTag]`, which `case`
uses for branch tests. The runtime reads the basic tags from `_int_tag`,
`_bool_tag`, and `_string_tag`.

## Global tables and constants

- `class_nameTab`: one word per tag pointing to the class-name `String`
  constant (used by `type_name` and runtime error messages).
- `class_objTab`: two words per tag, the prototype and the init method
  (`new SELF_TYPE` indexes it with self's tag × 8).
- `C_dispTab`: one word per method slot. A class starts with its parent's
  slots in order; an override replaces the parent's label in the same slot,
  and new methods are appended in declaration order, so a method has the
  same slot offset in every subclass. Basic methods (`Object.abort`,
  `Object.type_name`, `Object.copy`, `IO.out_string`, `IO.out_int`,
  `IO.in_string`, `IO.in_int`, `String.length`, `String.concat`,
  `String.substr`) are runtime labels.
- Constants: `str_constN` (every literal, every class name, every source file
  name for abort messages, and `""`), `int_constN` (every literal and every
  string length), and `bool_const0` / `bool_const1`, each a complete object
  with an eyecatcher.
- Memory manager: `_MemMgr_INITIALIZER` and `_MemMgr_COLLECTOR` name the
  collector (`_NoGC_Init`/`_NoGC_Collect`, or `_GenGC_Init`/`_GenGC_Collect`
  with `-g`), and `_MemMgr_TEST` is 1 with `-t`. `heap_start` ends the data
  segment.

## Calling convention and register invariants

| Register | Role |
| --- | --- |
| `$a0` | accumulator: every expression leaves its value here; self on method entry; the return value |
| `$s0` | self for the whole method body (callee-saved) |
| `$fp` | frame pointer (callee-saved) |
| `$ra` | return address (callee-saved) |
| `$t1`, `$t2`, `$a1` | scratch; never live across a call |
| `$sp` | points to the next free stack word; the stack grows down |

A call pushes the arguments in order (first argument first), evaluates the
receiver into `$a0`, checks it for void, loads the method from the dispatch
table (the receiver's table, or `T_dispTab` for `e@T.f(...)`), and calls it
with `jalr`. The callee saves `$fp`, `$s0`, and `$ra`, sets `$s0` to self, and
pops its own arguments when it returns. Frame layout after the prologue:

| Address | Contents |
| --- | --- |
| `fp + 12 + 4*(n-1-i)` | argument `i` of `n` |
| `fp + 8` | saved `$fp` |
| `fp + 4` | saved `$s0` |
| `fp + 0` | saved `$ra` |
| `fp - 4`, `fp - 8`, ... | temporaries and `let`/`case` variables |

Temporaries never live in registers across a call: binary operands, pending
arguments, and `let`/`case` variables are on the stack and `self` is in
`$s0`, so the garbage collector finds every live object. There is no limit on
the number of formals; all arguments are passed on the stack.

`C_init` runs the parent's init first (with self in `$a0`), then evaluates
the class's own attribute initializers in declaration order with self in
`$s0`, stores each one, and returns self. Initializers can therefore read
inherited attributes, already-initialized attributes, and dispatch on self.

## Expressions and runtime aborts

| Expression | Lowering |
| --- | --- |
| constants | `la $a0 int_constN` / `str_constN` / `bool_const0/1` |
| identifiers | `self` is `$s0`; formals and locals are `$fp`-relative; attributes are `$s0`-relative |
| `x <- e` | store into the same location; attribute stores call the collector hooks below |
| `e.f(...)`, `f(...)`, `e@T.f(...)` | the calling convention above |
| `new T`, `new SELF_TYPE` | `Object.copy` of the prototype, then the init method (`class_objTab` for `SELF_TYPE`) |
| `if`, `while` | branches on the `Bool` value at offset 12; `while` yields void |
| `{ ... }` | each expression in order |
| `let` | each binding's initializer or type default is pushed and addressed from `$fp` |
| `case` | tag-range tests, most specific branch first; the branch variable is pushed |
| `+ - * /` | `Object.copy` of the right operand, then `add`/`sub`/`mul`/`div` on the values |
| `~` | `Object.copy`, then `neg` |
| `< <=` | `blt`/`ble` choosing `bool_const1` or `bool_const0` |
| `=` | pointer identity, otherwise the runtime's `equality_test` |
| `not`, `isvoid` | test, then `bool_const1` or `bool_const0` |

Runtime errors use the runtime's entry points: dispatch on void calls
`_dispatch_abort` with the source file name (a `String`) in `$a0` and the line
in `$t1`; `case` on void calls `_case_abort2` with the same arguments; a
`case` with no matching branch calls `_case_abort` with the object in `$a0`.
Division by zero is left to the machine (SPIM's `div` traps); there is no
custom runtime routine for it.

## Garbage-collector flags

The collector is chosen with coolc's flags. **GUI:** the **Garbage
collector** checkboxes in the MIPS panel (`-g`, `-t`, `-T`) regenerate the
`.s` and configure the embedded simulator. **CLI:**
`coolerc emit assembly --target=mips -g -t -T` and
`coolerc run --target=mips -g -t -T`; the flags are rejected without
`--target=mips`, so default VM runs are unchanged.

| Flag | Effect on generated code |
| --- | --- |
| none | `_NoGC_Init` / `_NoGC_Collect` |
| `-g` | `_GenGC_Init` / `_GenGC_Collect`; every attribute store is followed by `_GenGC_Assign` with the attribute's address in `$a1` |
| `-t` | `_MemMgr_TEST` = 1: the collector runs at every allocation |
| `-T` | every attribute store first calls `_gc_check` with the stored object in `$a1` |

## Embedded simulator

`internal/mipssim` is a pure-Go, SPIM-compatible simulator that runs the
generated `.s` inside the app on desktop and mobile store builds. Nothing is
executed outside the process: it never invokes a host `spim`, and the store
apps have no runtime dependency on SPIM, Flex, Bison, `goyacc`, or the course
compiler.

- **Assembler:** SPIM's directives (`.data`, `.text`, `.align`, `.word` with
  numbers or labels, `.byte`, `.ascii`, `.asciiz`, `.space`, `.globl`) and the
  instructions and pseudo-instructions the backend emits (plus common
  arithmetic, logic, branch, and `syscall` forms). Labels the program uses
  without defining must be Cool runtime routines.
- **Memory:** SPIM's map — text at `0x00400000`, data at `0x10000000` with the
  heap after it, and the stack growing down from `0x7ffffffc`.
- **Cool runtime:** the documented contract of the runtime system, implemented
  natively: start-up (initialize the memory manager, copy `Main_protObj`, run
  `Main_init` and `Main.main`, print `COOL program successfully executed`),
  `Object.copy`/`abort`/`type_name`, the `IO` and `String` methods,
  `equality_test`, and the runtime errors `Dispatch to void.`,
  `Match on void in case statement.`, `No match in case statement for Class C`,
  `Abort called from class C`, and the `substr` range messages.
- **Memory managers:** the program's `_MemMgr_INITIALIZER` and `_MemMgr_TEST`
  words select the behavior, exactly as the runtime reads them. NoGC is a bump
  allocator. `-g` selects a non-moving mark-sweep collector (roots: every
  register and the stack from `$sp` to its top; precise inside objects) that
  reuses freed blocks and records `_GenGC_Assign` write barriers; `-t`
  collects before every allocation; `-T`'s `_gc_check` verifies the `-1`
  eyecatcher of every stored object. Freed blocks are poisoned, so a
  dangling pointer fails loudly. The run reports allocations, collections,
  freed objects, and heap size.
- **Input and output:** output goes to the MIPS panel; `IO.in_string` and
  `IO.in_int` read the Console's preloaded input, one line per read. When the
  program reads past it, the run stops with *waiting for input* and the panel
  shows a live input line; sending a line re-runs the deterministic program
  with the extra line. `in_int` trims spaces and reads 0 for a non-integer
  line, as Cooler's VM does.
- **Limits:** deterministic bounds on executed instructions (20 million by
  default), heap (64 MiB), stack (4 MiB), and output (4 MiB), plus
  cancellation; a fault (bad address, unsupported instruction, stack
  overflow, division by zero) is a contained runtime error, never a host
  crash.

Division by zero is reported as `Exception: division by zero.` (SPIM's `div`
trap); this text is simulator-specific, as is the wording of the other
machine faults above.

### Licensing review

`trap.handler` and the Cool runtime sources come from the course
distribution and SPIM; their redistribution terms were not verified for
store distribution. The decision is therefore to **reimplement the
documented contract** — the routine names, register and stack conventions,
start-up sequence, error messages, and memory-manager hooks described in the
Cool runtime-system documentation — in Go, and to bundle neither
`trap.handler` nor any SPIM source or binary. The generated `.s` still uses
the standard labels, so it also runs on a real SPIM with the user's own
`trap.handler`. Real SPIM is used only by the optional CI/dev comparison
(`TestLiveSimulatorMatchesSPIM`; `COOLER_REFERENCE_RUNNER`,
`COOLER_TRAP_HANDLER`, or the Cool root), which skips when the tools are
absent and fails under `STRICT=1`.
