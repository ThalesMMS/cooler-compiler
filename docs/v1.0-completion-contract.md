# Cooler v1.0.0 completion contract

This versioned contract defines the finite meaning of “100% complete” for
Cooler v1.0.0 and the evidence required before that version can be called
released. The current public release remains v0.1.0 until every step below is
complete and the exact qualified v1.0.0 candidate is published.

## Locked product scope

Cooler v1.0.0 includes:

- the classic COOL lexer, parser, static semantics, runtime, built-ins, and
  deterministic 32-bit `Int` behavior described by the
  [language contract](cool-language.md);
- ordered multifile `SourceUnit` compilation, typed AST, symbols, stack IR,
  CFG, pseudo-assembly, bytecode verification, and optional verified
  educational optimization;
- bounded deterministic compiler and VM sessions, interactive input,
  source-level and reverse debugging, breakpoints, watches, logpoints, heap
  inspection, and relationship visualizations;
- the CLI, local browser and native GUIs, reports, exports, versioned schemas,
  stable public Go API, and local COOL LSP; and
- rule-level conformance, local differential, fuzz, property, stress, race,
  benchmark, reproducibility, packaging, and target-runtime evidence.

The normative details remain in the linked interface and language documents.
This checklist freezes their integrated v1.0.0 boundary; it does not replace
those contracts.

## Intentional non-goals

The release does not promise MIPS/SPIM output or reference-runtime ABI
compatibility, modules/imports/linking, native machine-code generation, a
hosted or multi-user compiler/debugger service, hosted fuzzing or benchmarks,
GitHub Actions, hosted CI, or CI badges. These are product boundaries, not
exceptions for missing classic COOL language behavior.

No new feature may enter v1.0.0 without explicitly reopening
[Final 01/11](https://github.com/ThalesMMS/cooler-compiler-dev/issues/51),
reviewing the scope change, and invalidating any dependent evidence as needed.

## Completion states

The following states are separate and must never be inferred from one another:

- **Implemented:** the required source, tests, fixtures, schemas, and
  documentation exist in `main`.
- **Locally verified:** the exact committed tree passed the issue-specific
  checks and, when required, the complete local release gate.
- **Target-runtime verified:** the exact artifact hashes built from the frozen
  candidate ran successfully on every advertised OS/architecture.
- **Publicly released:** the byte-equivalent sanitized tree, annotated tag, and
  already-qualified artifacts are public and their downloaded bytes and
  clean-clone workflows have been verified.

Only the final state makes v1.0.0 a supported public release.

## Sequential main-only protocol

The final sequence is maintainer work performed directly on `main`, without
implementation branches or pull requests. Finish one issue before starting the
next: validate its premise and acceptance criteria, implement or close it as
invalid, execute its checks, correct every relevant failure, commit and push,
then add a closing comment with the exact commit SHA, commands, pass/fail/skip
results, and retained intentional boundaries.

A later regression reopens the earliest issue whose contract was violated. Any
tracked-file change after the candidate is frozen invalidates that candidate;
source or documentation changes during artifact qualification or publication
also invalidate all dependent artifacts and evidence.
